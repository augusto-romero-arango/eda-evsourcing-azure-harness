- El modulo `container-app` que genera `infra-base-scaffolder` (Paso 1.9.3) cede a CI la propiedad de la imagen del worker de proyecciones: `azurerm_container_app.this` gana un bloque `lifecycle { ignore_changes = [template[0].container[0].image] }`, para que el `az containerapp update --image` del pipeline de imagen (fuera de alcance de este agente) no sea revertido por el siguiente `terraform plan`. `var.image`/`var.projections_worker_image` y su default placeholder (`mcr.microsoft.com/k8se/quickstart:latest`) no cambian -- solo alimentan el `create` del bootstrap. Se corrige, ademas, la prosa del modulo, la descripcion de `var.image`, la nota de placeholder y el reporte final (Paso 5) para dejar de instruir que hay que actualizar `projections_worker_image` para desplegar la imagen real, y se documenta la contrapartida del reparto: como `ignore_changes` si considera el atributo al planificar un `create`, un Container App **recreado** vuelve al placeholder y exige re-publicar la imagen (Terraform no restituye el tag real, que no vive en el HCL) -- el mismo comportamiento que ya tiene una Function App recreada frente a `Azure/functions-action`.
