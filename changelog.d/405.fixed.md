- **La fase *prepare* de `/mefisto-release` ya no vuelca las notas completas del CHANGELOG en el body del PR de release, cerrando el issue #405**: `mefisto-release.sh` interpolaba `extract_version_section` (las notas integras de la seccion versionada) directo en el body via `gh pr create --body-file`, y la seccion `[0.18.0]` real media 109.010 caracteres -- 1.66x el limite de 65.536 de la API GraphQL de GitHub -- lo que aborto la publicacion de v0.18.0 (PR #404 hubo que abrirlo a mano). Se agrega `summarize_version_section`, que recibe las notas completas y emite un indice de las 4 categorias Keep a Changelog (Added/Changed/Fixed/Removed) con el conteo de entradas de cada una: su tamano queda acotado por el numero fijo de categorias, no por el volumen de las entradas, asi que no vuelve a romperse cuando el CHANGELOG crezca. El conteo descarta los bloques cercados con backticks triples, porque una entrada de este repo puede embeber un snippet y una linea `- ...` dentro del snippet inflaria el indice en silencio. Si la seccion no trajera subsecciones `### Categoria` (entradas escritas a mano sin pasar por `changelog.d/`), el resumen sale vacio y el body cae a una linea de fallback en vez de quedar con una seccion muda. `extract_version_section` no se toco -- las notas integras siguen viviendo en el CHANGELOG, en el diff del propio PR y en el GitHub Release de la fase *publish*. El body del PR suma un enlace navegable a `CHANGELOG.md` en la rama de release (owner/repo derivados de `gh repo view`, sin hardcodear) para llegar a las notas completas en un clic. Se verifico ademas el limite de `gh release create --notes-file` (fase *publish*): la documentacion oficial de la REST API no declara un maximo para `body`, pero el limite que la API aplica es 125.000 caracteres, verificado en el HTTP 422 que devuelve (`body is too long (maximum is 125000 characters)`) segun dos reportes independientes (`cli/cli#7705`, `changesets/action#304`) -- con margen holgado sobre los 109.010 medidos --, asi que esa fase queda sin cambios, documentado con un comentario que cita las tres URLs completas.
