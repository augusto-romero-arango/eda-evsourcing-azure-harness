- Se corrige un falso fallo de merge en `pr-sync.sh`: `desbloquear_issues_dependientes()` abortaba con `unbound variable` bajo `/bin/bash` 3.2 (macOS) cuando un issue bloqueado referenciaba el issue recien cerrado con una redaccion no canonica en su seccion `## Dependencias` (p. ej. "Depende del write-side: #N"), dejando el array de dependencias vacio. El crash contaminaba el exit code del merge, que ya habia sido exitoso, y ademas dejaba issues con el label `bloqueado` de mas. Ahora la funcion no aborta con un array vacio, emite un `warn` identificando el issue y la redaccion no parseable, y las dos invocaciones post-merge aislan su exit code (`|| warn`) del resultado del merge. Los dos cambios cubren cosas distintas y ambos hacen falta: un abort por `set -u` mata el shell sin pasar por el `||`, asi que el aislamiento **no** habria salvado el merge por si solo -- la guardia de longitud es el fix de fondo y el `|| warn` es la red para los demas modos de fallo del post-merge (fallos de `gh`, de `jq` o de red al consultar el estado de las dependencias). El test `scripts/tests/test-pr-sync-desbloqueo.sh` corre la funcion extraida con `/bin/bash` **y** `set -euo pipefail` explicitos, porque sin las opciones de shell de produccion la version pre-fix no crashea sino que falla de otro modo, mas silencioso (recorre el array vacio, concluye "todas las dependencias cerradas" y desbloquea el issue por error).
