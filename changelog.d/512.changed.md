- `domain-scaffolder` propaga al write-side el apagado en origen del durability agent de Wolverine (MEF-ADR-0038 seccion 6): la receta de `ComposicionServicios{Dominio}` fija `options.Durability.DurabilityMetricsEnabled = false;` al inicio del callback de `AgregarWolverineParaComandosServerless` -- el punto en que sobrevive a la reasignacion incondicional posterior de `Durability.Mode = Solo` que hace el paquete (verificado por decompilacion), sin tocar `Mode` ni `DurabilityAgentEnabled`. El test de composicion generado (`ComposicionContenedorTests`) suma dos guardrails deterministas sobre `WolverineOptions` resuelto del contenedor real: `DurabilityMetricsEnabled == false` y, en un test aparte, `DurabilityAgentEnabled == true` + `Mode == DurabilityMode.Solo` (durabilidad real intacta). El Paso 7 (verificar) documenta las cuatro formas de falla de esos dos guardrails -- incluido el `CS1061` si un upgrade retira los miembros -- para que ninguna se resuelva borrando el test o fijando `Mode` desde el callback. Miembros, defaults (`DurabilityMetricsEnabled`/`DurabilityAgentEnabled` en `true`, `UpdateMetricsPeriod` en 5 s) y el namespace de `DurabilityMode` verificados contra la documentacion XML de `Wolverine` 6.16.0, la version que arrastra `Cosmos.EventSourcing.CritterStack` 2.3.1.
