- Se derivan metricas por stage del pipeline interno `mefisto-tooling` a partir de la traza `stream-json` que ya persiste `run_agent` (issue #425). La funcion nueva `compute_stage_metrics` (`.claude/scripts/_mefisto-common.sh`) lee el stream crudo de cada stage y extrae `turns`, `duration_ms`, `duration_api_ms`, `non_api_ms` (derivado), `cost_usd`, `tokens` desglosados (`input`/`output`/`cache_read`/`cache_creation`), `model`, `is_error`/`stop_reason`/`terminal_reason`, y un histograma de tool calls por nombre con `count` y tiempo atribuido (suma y mediana) via emparejamiento `tool_use.id` <-> `tool_use_id`, ambos fechados por el `timestamp` ISO-8601 de cada evento. Se escribe un JSON por stage bajo `.claude/pipeline/metrics/` y se anida bajo `agents.<agente>.metrics` tanto en la entrada `completed` de `pipeline-history.jsonl` como en la entrada `failed` que emite `abort()` -- antes esta ultima no llevaba ninguna cifra por agente, y los fallos son los casos mas caros de entender. La funcion nueva `build_agents_history_json` construye ese objeto `agents` agregando `metrics` sin tocar el campo `duration` existente (en segundos, sin cambios). Degrada con gracia si falta `jq`, la traza esta truncada, o el evento `result` no existe: la entrada se emite igual (sin `metrics`) y el pipeline no aborta ni cambia su exit code por un fallo de instrumentacion. Este issue solo persiste las cifras; el analisis agregado es un issue aparte.
