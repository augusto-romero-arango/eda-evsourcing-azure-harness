- El pipeline interno de entrega de field notes (`mefisto-field-note.sh`) resolvia la rama predeterminada con `gh repo view --repo <slug>`, un flag que `gh repo view` no acepta (recibe el repositorio como argumento posicional): abortaba en toda invocacion real antes de crear el worktree, dejando el cierre documental de `mefisto-planner` sin salida. Corregido a la forma posicional (`gh repo view <slug> --json defaultBranchRef`); el mensaje de error de ese paso ya no atribuye el fallo unicamente a `gh auth status`, tambien senala un argv invalido como causa posible. El stub de `gh` que usan los tests ahora rechaza `--repo`/`-R` en `repo view` en vez de aceptar cualquier flag por coincidencia de substring, para que una regresion de argv como esta vuelva a fallar el test.
