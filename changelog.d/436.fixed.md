- Se extrae el bloque bash de ~95 lineas de la validacion de dependencias intra-batch
  (paso 1.5 de `.claude/commands/mefisto-sequential.md`) a un script propio,
  `.claude/scripts/mefisto-validate-batch-deps.sh`. El bloque vivia incrustado en el
  markdown del skill con sintaxis posicional de shell (`$1`, `$*`, `$#`) -- y Claude Code
  expande los placeholders `$N` del ARCHIVO DEL COMANDO antes de entregar su contenido al
  modelo, asi que el agente nunca leia el codigo que habia en disco, sino una version
  corrompida (`local target="437"` fijo, tomado de un argumento real de la invocacion, en
  vez de `local target="$1"`). El sintoma no fallaba: `pos_in_batch` comparaba todos los
  issues contra un unico numero fijo, y la clasificacion de dependencias intra-batch
  (satisfactible / mal ordenada / bloqueo real) daba resultados falsos en silencio, sin
  exit code que lo delatara, en la unica validacion que existe para no lanzar un batch mal
  ordenado. Un fix previo (#441) habia partido de la premisa de que la sustitucion la hacia
  el agente (no el harness) y la habia reforzado con prosa ("copia el heredoc verbatim"),
  sin resolver el mecanismo real. Un script en disco lo lee `bash`, no el constructor de
  prompts de Claude Code: ningun `$N` puede corromperse ahi, y la clase entera de defecto
  desaparece en vez de un caso puntual. El paso 1.5 ahora invoca el script con la lista de
  issues del batch como argumentos y su contrato de tres exit codes (`0` lanza, `1` aborta
  por bloqueo real, `2` invocado sin argumentos).
