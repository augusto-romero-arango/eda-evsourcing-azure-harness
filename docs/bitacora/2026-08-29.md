# 2026-08-29 - El planner descubre que no puede usar las herramientas MCP que ya ve

> Reproducir en la propia sesión el bug reportado desde el consumidor confirmó la causa raíz en un renglón: la allowlist `tools:` del planner nunca declaró ningún `mcp__*`, así que veía las instrucciones del servidor pero no podía invocarlo -- el mismo hallazgo destapó, de paso, que el MCP de terraform llevaba tiempo corriendo en degradación silenciosa en `infra-writer`.

## Lo que se logró

- **Causa raíz de #753 confirmada y reproducida en la propia sesión**: la allowlist `tools:` de `agents/planner.md` no incluía ningún `mcp__*`, lo que bloqueaba las herramientas MCP aunque las instrucciones del servidor sí se inyectaban al contexto -- el agente "veía" el servidor pero recibía `No such tool available`. Se decidió (alternativa A del usuario, sobre la opción B de detección opt-in vía `/onboard`) que Mefisto **bundlee el MCP de Microsoft Learn en su propio `plugin.json`**, para que todo consumidor lo obtenga automático, aceptando explícitamente el costo de contexto en todas las sesiones de pipeline. #753 se refinó a `estado:listo` y cerró el mismo día: PR #755 declara el servidor y habilita el wildcard `mcp__plugin_mefisto_microsoft-learn__*` en el planner publicado.
- **Hallazgo colateral confirmado con evidencia local**: el MCP de terraform llega al repo vía plugin (`claude-plugins-official/terraform`, stdio docker `hashicorp/terraform-mcp-server:0.4.0`), así que el wildcard `mcp__terraform__*` que declaraba `infra-writer` nunca casaba con el nombre real scoped (`mcp__plugin_terraform_terraform__*`) -- ese agente llevaba tiempo corriendo sin terraform MCP, en degradación silenciosa. #754 (bug) se creó y cerró el mismo día: PR #756 declara **ambas** formas del wildcard (la corta y la scoped), inocuo cuando una no existe.
- **Inventario de servidores MCP oficiales** (vía `gh api search`, 2026-08-29): Microsoft Learn sí tiene uno oficial y documental (`MicrosoftDocs/mcp`, endpoint HTTP remoto sin auth); Azure tiene uno oficial pero operativo -- opera recursos vivos, requiere `az login` -- no documental; Marten/Wolverine/JasperFx y NuGet/dotnet no tienen ninguno. Confirma y documenta el **formato scoped oficial** de tools MCP de plugin: `mcp__plugin_<plugin>_<server>__<tool>` (code.claude.com/docs/en/plugins-reference, sección "MCP servers") -- un matcher contra el nombre corto del servidor nunca casa cuando el servidor llega vía plugin.
- **#759 cierra la cadena de automatización de `/mefisto-release`**: PR #760 encadena merge, sync y publish automáticamente tras la fase prepare, evitando los pasos manuales que hasta entonces seguían al `prepare`.
- **Dos releases el mismo día**: v0.30.0 (PR #752) consolida el paquete del día anterior (MEF-ADR-0046 + purga de store); v0.31.0 (PR #758) consolida el bundle de MCP + fix del wildcard de terraform + la cadena de `/mefisto-release`.

## Problemas encontrados

1. **Un agente puede "ver" un servidor MCP entero (sus instrucciones se inyectan igual) y aun así no poder usarlo**: el fallo no es de configuración del servidor sino de la allowlist `tools:` del agente que lo consume -- un tipo de bug que no deja rastro visible salvo el mensaje `No such tool available` en el momento exacto de la invocación.
2. **Un wildcard MCP mal escrito no rompe nada de forma ruidosa**: `infra-writer` llevaba tiempo (no cuantificado en la sesión) corriendo sin acceso al MCP de terraform porque el wildcard corto nunca casaba con el nombre scoped real -- degradación silenciosa, descubierta solo por cruzar el hallazgo de #753 contra otros agentes con wildcards MCP.

## Lo que descartamos

- **Detección opt-in del MCP de Microsoft Learn vía `/onboard`** (alternativa B): se prefirió el bundle automático en `plugin.json`, para que todo consumidor lo tenga sin pasos adicionales.
- **Dar al planner el Azure MCP** (`Azure/azure-mcp`): opera recursos vivos, no documentación -- fuera del propósito de verificación de fuentes del planner.
- **WebFetch/WebSearch como sustituto para documentación de Marten/Wolverine** (sin MCP oficial disponible): fuera de alcance de #753; queda como necesidad no resuelta.
- **Corregir el wildcard de terraform dentro de #753**: componente distinto (`infra-writer` vs `planner`) -- se separó en su propio issue, #754.
- **Extender el alcance de #753 a otros agentes además del planner publicado**: se acotó al planner; extender a más agentes queda como decisión futura con evidencia propia.

## Aprendizajes

1. **La allowlist `tools:` de un agente y las instrucciones que un servidor MCP inyecta al contexto son dos capas independientes**: la segunda no implica la primera -- un agente puede citar y razonar sobre un servidor que no puede invocar, y el único síntoma es el rechazo puntual de la tool call.
2. **El formato scoped `mcp__plugin_<plugin>_<server>__<tool>` no es opcional cuando el servidor llega empaquetado en un plugin**: un wildcard escrito contra el nombre corto del servidor nunca casa, y el fallo es silencioso -- ningún error se levanta, el agente simplemente corre sin esa herramienta.
3. **Reproducir el bug reportado en la propia sesión de refinamiento, antes de escribir el issue, confirma la causa raíz con evidencia de primera mano** en vez de aceptar la hipótesis del reporte original -- y de paso permite cruzarla contra otros agentes con el mismo patrón de wildcard, como pasó con `infra-writer`.
