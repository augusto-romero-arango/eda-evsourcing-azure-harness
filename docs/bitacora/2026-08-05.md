# 2026-08-05 - El día en que Mefisto se hizo un historiador propio

> La cola del batch nocturno de telemetría cerró a media mañana, el paso 2 del plan de velocidad quedó entregado, y el harness construyó -- en el mismo día -- el agente y los skills que producen esta misma bitácora: la primera vez que Mefisto se documenta con una herramienta hecha a propósito para documentarse.

## Lo que se logró

- **La cola del batch de MEF-ADR-0038 cerró (#513 → PR #525)**: el sampler del worker de proyecciones con filtro del daemon, última pieza de la cadena lanzada la noche anterior, mergeada ya entrada la mañana.
- **El historiador se evolucionó de mono-día a multi-día, en cuatro issues (#527 → PR #532, #528 → PR #536, #529 → PR #537, #530 → PR #538).** Diagnóstico de partida: Mefisto tenía **un solo** historiador -- el agente publicado `agents/historiador.md`, sin slash command que lo invocara -- y **ningún** historiador interno; las bitácoras de este propio repo se habían creado invocando el agente publicado a mano, que ni siquiera se carga al abrir este repo (Claude Code solo carga `.claude/agents/`). El historiador existente era además mono-día (`FECHA=${1:-$(date +%Y-%m-%d)}`), ciego a su propio backlog -- dolor medido en 15 field notes sin procesar en el momento del diagnóstico. Se resolvió con: una entrada por cada día con notas pendientes, un solo PR por sesión de historiador (no uno por día), movimiento selectivo a `procesadas/`, y un contrato explícito agente→skill (el historiador reporta el número de PR; el skill orquestador encadena el merge) -- necesario porque **un subagente no puede invocar slash commands**, restricción de diseño ya resuelta antes por el patrón `/install-auth` (skill → agente → skill).
- **`/mefisto:upgrade`, skill publicado para actualizar el plugin desde el consumidor (#531 → PR #539).** Hoy el proceso es manual y propenso a error: UI de `/plugin` → actualizar, editar a mano `.claude/pipeline/.plugin-root`, limpiar caché de versiones viejas, `/reload-plugins`. Se descubrió que el CLI ya tiene primitivas no interactivas verificadas localmente (`claude plugin update <plugin> --scope user`, `claude plugin marketplace update <name>`) que vuelven innecesaria la UI. La poda del caché conserva siempre {versión nueva, versión cargada en la sesión actual} y pide confirmación -- nunca se borra la versión que la propia sesión activa tiene cargada.
- **Dos mejoras de resiliencia y ergonomía del pipeline interno**: #534 (reintentar con backoff la invocación del agente cuando el fallo es `API_ERROR_SERVER`, PR #535) y #533 (skill interno `/mefisto-tooling-verbose` que delega en `/mefisto-tooling` y abre directamente el pane del visor en vivo, PR #540).

## Problemas encontrados

1. **Un subagente no puede invocar slash commands** -- restricción de diseño que obligó a partir la arquitectura del historiador en cuatro piezas (agente publicado, skill publicado `/bitacora`, agente interno `mefisto-historiador`, skill interno `/mefisto-bitacora`) en vez de un solo componente autosuficiente.
2. **El historiador que existía hasta ayer era ciego a su propio backlog** -- la evolución de hoy es, en sentido estricto, la primera vez que se ejerce el historiador nuevo sobre el backlog acumulado que motivó su propia creación.
3. **La cola del batch nocturno de MEF-ADR-0038 (#513) no cerró en la misma sesión que la lanzó** -- se resolvió ya entrada la mañana de hoy, evidencia de que un batch largo puede extenderse más allá de la sesión que lo inició.

## Lo que descartamos

- **Un PR por día con notas pendientes**: seis ciclos de push/PR/merge por sesión de historiador, fricción sin valor. Se prefirió un solo PR por sesión, con una entrada por día dentro de él.
- **Gate de confirmación adicional antes del merge automático del PR de bitácora**: redundante -- el gate humano real es la aprobación conversacional de cada borrador dentro del historiador; el PR es solo el vehículo.
- **Que el propio agente historiador mergee con `gh pr merge` directamente**: el usuario pidió explícitamente reusar los skills de merge existentes (`/merge` publicado, `/mefisto-merge` interno), centralizando esa lógica en un solo lugar por lado.
- **Podar el caché de versiones del plugin desde el hook `SessionStart`**: correría en cada sesión, incluidas las headless de pipelines en tmux, con riesgo real de borrar la versión que un batch en curso tiene cargada.

## Aprendizajes

1. **Un problema de arquitectura (subagente que no puede invocar skills) ya tenía un patrón resuelto en el propio repo** -- reconocer el precedente de `/install-auth` evitó reinventar el mecanismo de encadenamiento agente→skill.
2. **Automatizar una tarea manual y propensa a error exige primero verificar qué primitivas ya expone la herramienta subyacente**, antes de diseñar alrededor de su UI -- la UI de `/plugin` resultó innecesaria en cuanto se encontraron los comandos no interactivos del CLI.
3. **Documentar una herramienta antes de que exista el dolor medible no la habría motivado igual** -- la evolución del historiador nació de un número concreto (15 field notes sin procesar), no de una hipótesis.
4. **Cerrar el ciclo de un plan de mejora de proceso (paso 2 del plan de velocidad, iniciado el 2026-07-27, medido el 2026-08-04) mientras en paralelo se construye la herramienta que va a documentar ese mismo ciclo de aquí en adelante** es la clase de recursividad que ningún otro día de este backlog tuvo.
