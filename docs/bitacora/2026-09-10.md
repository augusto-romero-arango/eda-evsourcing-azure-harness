# 2026-09-10 - El consumidor sintético empieza a morder

> Bootstrapear el consumidor real de certificación, sin atajos ni parches manuales, encontró en un solo día tres defectos que ningún fixture había reproducido: un backend de CI mal resuelto, un agente que ignoraba el config canónico y unos subjects OIDC que GitHub ya no deja mutar.

## Lo que se logró

- **El consumidor privado de certificación completó su primer backend Terraform real** con naming CAF bajo Mefisto v0.37.2, y detectó de inmediato que `setup-github-ci.sh` mezclaba una Storage real con un Resource Group legacy inexistente al asignar el rol de datos sobre el tfstate.
- **Corregimos `setup-github-ci.sh` para resolver RG y Storage como una sola pareja del mismo backend efectivo** (#1208), en vez de resolver cada valor de forma independiente — lo que permitía mezclar ambientes cuando existía más de uno. La corrección se probó de forma hermética, con `az` y `gh` stubbeados, cubriendo CAF, legacy, entrada inválida y reejecución parcial.
- **Publicamos v0.37.2 y v0.37.3** y repetimos el bootstrap: la segunda corrida de `setup-github-ci.sh` fue idempotente (reutilizó la app/SP, dejó exactamente una asignación de cada rol y dos credenciales federadas sin client secret) y `/onboard` pasó de varios `NO VERIFICADO` a solo tres pendientes triviales.
- **Encontramos que `infra-base-scaffolder` todavía leía `.claude/harness.config.json` directamente**, pese a que MEF-ADR-0053 ya había declarado `.mefisto/harness.config.json` como contrato canónico. Se corrigió en #1212 con precedencia canónico/fallback tanto en el agente como en el workflow generado, verificado con la prueba contractual (13/0) y los guards (202/0).
- **Bootstrapeamos la infraestructura base sin créditos Claude**, mediante una ejecución OpenCode one-shot de `infra-base-scaffolder` ya corregido — bootstrap explícito, no evidencia de paridad ni migración formal del catálogo, porque MEF-ADR-0053 sección 6 prohíbe migrar el resto del catálogo antes de certificar el corte vertical de tooling.
- **Publicamos v0.37.4 y v0.37.5** después de descubrir y corregir que los subjects OIDC generados por CI no eran estables frente a los que GitHub ya no permite mutar una vez creados.

## Problemas encontrados

1. **Un script de bootstrap resolvía dos valores relacionados por separado** (Resource Group y Storage Account del backend), lo que solo se manifestaba como fallo cuando existía más de un ambiente — un defecto invisible en cualquier fixture con un solo backend.
2. **Un reviewer quedó huérfano al expirar el timeout externo durante #1212** dentro del pipeline interno OpenCode; alcanzó a detectar que cada bloque bash independiente debía recomputar `REPO_ROOT` y `CONFIG` antes de morir. El pipeline se retomó desde Stage 2 y conservó esas correcciones — otra confirmación de que un timeout duro no invalida el trabajo ya hecho.
3. **`/infra-base` no tenía un generador determinista de HCL**: delega la escritura inline al agente `infra-base-scaffolder`, lo que significó que bootstrapear sin créditos Claude no era tan simple como "correr un script"; exigió replicar la doctrina exacta bajo OpenCode como ejecución one-shot, explícitamente distinta de una migración formal.
4. **Los subjects OIDC de GitHub son inmutables una vez creados**: un primer intento de corrección que asumía poder ajustarlos in situ no era viable; hubo que resolverlos correctamente antes de la primera creación.

## Lo que descartamos

- **Crear manualmente el role assignment o las federated credentials faltantes** para simular éxito: habría ocultado el defecto real de la release que se estaba certificando.
- **Borrar la app/SP y los roles ya creados** para partir de cero: el contrato del bootstrap es idempotente y la repetición debía demostrarlo tal cual, no tras un reseteo.
- **Elegir el primer RG y la primera Storage encontrados por separado**: permitiría mezclar ambientes sin que ningún error lo detectara.
- **Portar formalmente `/infra-base` a OpenCode antes del gate de tooling**: MEF-ADR-0053 sección 6 prohíbe migrar el resto del catálogo antes de certificar el corte vertical `/mefisto:tooling`; el bootstrap fue una ejecución puntual, no una migración.
- **Alimentar al agente con una instrucción ad hoc que ignorara la ruta legacy conocida**: sería un workaround sobre un defecto ya identificado, en vez de corregirlo en el harness y regenerar la evidencia.

## Aprendizajes

1. **Un consumidor sintético con infraestructura real encuentra clases de defectos que ningún fixture aislado reproduce**: la pareja RG/Storage, el config canónico ignorado y los subjects OIDC inmutables solo aparecieron al ejecutar contra Azure y GitHub de verdad.
2. **MEF-ADR-0053 exige corregir el harness y republicar, nunca parchear el consumidor**: cada defecto encontrado durante la certificación se resolvió en el repo de Mefisto, se probó, se publicó como patch y solo entonces se repitió la operación sobre el consumidor.
3. **La idempotencia de un bootstrap solo se demuestra repitiéndolo, no razonando sobre el código**: la segunda corrida de `setup-github-ci.sh` fue la evidencia real de que la corrección no dejaba estado duplicado.
4. **Un timeout externo puede llevarse un proceso pero no necesariamente el trabajo útil que ya alcanzó a producir**: recuperar la corrección detectada por el reviewer huérfano evitó repetir un diagnóstico ya hecho.
