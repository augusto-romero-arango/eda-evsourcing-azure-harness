# 2026-07-16 - El refactor que no debía fallar, y las cinco grietas que destapó al validarse

> Una pregunta simple del mantenedor -- ¿por qué un issue `tipo:refactor` hace fallar el pipeline si por definición no genera tests nuevos? -- destapó una falla real en el carril de señal de refactor y, al intentar validarla contra un consumidor real (`Cosmos-SincoERP/Cosmos.ControlPlane`), una familia entera de cinco bugs de deriva harness-consumidor más; cada uno se liberó apenas se cerró, produciendo cinco releases (v0.14.0 → v0.14.4) en una sola jornada.

## Lo que se logró

- **v0.14.0 (07:20 local)**: empaquetó dos cierres. El de **#294** (fix nacido la noche anterior, cerrado 2026-07-15 23:25 local, justo antes de la medianoche) que extiende el carril de señal de refactor de `agents/test-writer.md` para cubrir refactors a nivel de firma de tipo (quitar una interfaz marker, un parámetro de constructor, mover un tipo de proyecto) que además eliminan tests obsoletos -- caso que el test-writer venía interpretando como descalificador del carril, ejecutando el refactor él mismo y disparando el Gate 1b anti-trampa. Nuevo campo `REMOVED_TESTS=<n>` en la señal; el gate "no deben perderse tests" de `tdd-pipeline.sh` pasa a tolerar `allowed_min = BASELINE_TEST_COUNT - REMOVED_TESTS`. ADR-0017 enmendado (Decisión + nueva sección Control de cambios). Y el de **#295** (PR #297), el primero de la familia de bugs de deriva: `batch-pipeline.sh` invocaba `pr-sync.sh` con ruta relativa al cwd del consumidor (donde ese script no existe), y `tooling-pipeline.sh` hacía `sed` sobre `.claude/settings.json` sin el guard `[ -f ]` que `tdd-pipeline.sh` sí tenía.
- **v0.14.1 (07:51 local)**: fix directo del mantenedor (sin issue propio) para **#299** -- `pr-sync.sh` mergeaba con `--merge` hardcodeado y fallaba en repos squash-only (el consumidor tiene ruleset de historia lineal + `allow_merge_commit=false`); el retry ocultaba la causa real repitiendo "estado: CLEAN" en vez de reportar el método rechazado.
- **v0.14.2 (09:44 local)**: fix directo del mantenedor para **#302** -- el gate de tests de `tooling-pipeline.sh` corría `dotnet test --solution` (toda la solución, incluidos los `*.SmokeTests` black-box contra dev, sin credenciales en un run local) y abortaba con falsos 401/404. `tdd-pipeline.sh` ya los excluía vía `run_tests_projects`; tooling no.
- **v0.14.3 (12:06 local)**: cierre de **#305** (PR #306) -- el mismo bug de smoke tests, esta vez en el tercer gate (`pr-sync.sh`, el último sin el fix). Al corregirlo se descubrió que `run_tests_projects` y `extract_test_count` estaban duplicadas byte a byte en `tdd-pipeline.sh` y `tooling-pipeline.sh`; se consolidaron en `scripts/_pipeline-common.sh` (parametrizando la ruta del worktree) para que los tres pipelines compartan una sola fuente de exclusión.
- **v0.14.4 (20:51 local)**: cierre de **#308** (PR #309) -- declaraciones `local` fuera de función en `tooling-pipeline.sh:493` y `tdd-pipeline.sh:334`, que bajo `set -e` mataban el pipeline con `local: can only be used in a function` antes de llegar al `abort()` limpio. Detectado con `shellcheck` (regla SC2168); nuevo `scripts/tests/test-no-toplevel-local.sh` como guard estático permanente.

## Problemas encontrados

- **El síntoma original**: el batch del consumidor abortó en Stage 1 con `Stage 1 fallido: todos los tests pasan (exit code: 0) — el test-writer pudo haber escrito implementación real en lugar de stubs`, al procesar un issue `tipo:refactor` del consumidor que reclasificaba un evento (quitar `IPublicEventSender`, mover el tipo de proyecto). El test-writer hizo el refactor completo él mismo, dejó la suite verde, y el Gate 1b (anti-trampa) lo interpretó -- correctamente, dado su contrato -- como una violación.
- **Un segundo gate rígido esperaba agazapado detrás del primero**: aunque el test-writer hubiera emitido la señal de refactor puro, el gate "no deben perderse tests" de Stage 3 también habría abortado, porque este tipo de refactor borra legítimamente tests que ya no tienen canal que testear (sin marker de bus no hay `XPortabilidadTests.cs` que valga). El conteo baja de forma legítima y el gate no lo distinguía de una regresión real.
- **La familia de cinco bugs solo se hizo visible dogfoodeando contra un consumidor real.** Ninguno se había manifestado en el propio Mefisto -- todos son asimetrías entre scripts publicados que corren desde el cache del plugin pero asumen el layout del harness o la presencia de archivos que un consumidor concreto (`Cosmos-SincoERP/Cosmos.ControlPlane`) no tenía, o divergencias entre los tres gates de tests (`tdd`, `tooling`, `pr-sync`) que fueron creciendo con el tiempo sin que nadie las hubiera notado.
- **El crash de #308 enmascaraba el `abort()` limpio.** El error crudo de bash aparecía antes de que el pipeline pudiera marcar `state: failed`, dejando el `pipeline-status-*.json` en `running` y el worktree/sesión tmux huérfanos -- el operador veía un stacktrace de shell en vez de un mensaje claro.
- **#295 se reabrió a propósito.** Cerrarlo con solo el fix de #297 habría sido prematuro: #299 destapó un tercer bug (el método de merge) que seguía rompiendo el objetivo real ("el merge del batch funciona end-to-end"). Se mantuvo abierto hasta que los tres fixes de la familia estuvieron liberados.

## Lo que descartamos

- **Opción B para #294** (dejar que el test-writer haga el cambio de producción y solo señalice después): descartada -- contradice el contrato tajante del agente ("nunca escribes implementación real", líneas 8/34/830 de `agents/test-writer.md`) y debilita el Gate 1b anti-trampa, que existe justamente para detectar esto.
- **Enrutar por label en vez de por juicio del agente**: se mantuvo explícitamente fuera de alcance. `tipo:refactor` solo elige el pipeline (TDD); la clasificación refactor-vs-TDD sigue siendo juicio por-issue del test-writer (ADR-0017) -- un `tipo:refactor` puede necesitar tests nuevos y no todo lo que llega con ese label es refactor puro.
- **Documentar el `local` fuera de función como "no hacer"** en vez de arreglarlo (#308): descartado; se eliminó en ambas ocurrencias (quedan como asignaciones a nivel de script) y se agregó el guard estático de `shellcheck`, en vez de dejarlo como advertencia en la guía.
- **Limpiar worktree/tmux huérfanos como parte de #308**: sacado de alcance -- el `abort()` deja el worktree a propósito, para post-mortem, y el ciclo de vida de tmux lo gestiona `tmux-pipeline.sh`; endurecer eso es otro issue.

## Aprendizajes

1. **Un refactor a nivel de firma de tipo no tiene estado rojo que compile.** Quitar una interfaz marker o un parámetro de constructor obliga a que producción y tests cambien juntos para siquiera compilar -- el carril TDD normal es imposible para esta clase de cambio, y el carril de señal es el único válido. Matiz que la guía del test-writer no contemplaba hasta hoy.
2. **Borrar tests obsoletos no descalifica un refactor puro.** En el carril de señal, esos borrados/ajustes los hace el reviewer en Stage 3, no el test-writer -- confundir ambos roles fue justo lo que disparó el Gate 1b en el síntoma original.
3. **La deriva harness-consumidor solo se detecta dogfoodeando contra un consumidor real, no auditando el propio repo.** Los cinco bugs de esta familia (#295, #299, #302, #305, #308) llevaban tiempo latentes; ninguno tenía un caso de prueba dentro de Mefisto porque Mefisto no tiene el layout que los dispara.
4. **Código duplicado entre pipelines es deriva silenciosa.** `run_tests_projects` y `extract_test_count` vivían copiadas byte a byte en `tdd-pipeline.sh` y `tooling-pipeline.sh`; cuando una se corrigió y la otra no, quedó una asimetría invisible hasta que un tercer gate (`pr-sync.sh`) la repitió. Consolidar en `_pipeline-common.sh` es la única forma de que los tres compartan la misma corrección de una vez.
5. **`shellcheck` (regla SC2168) es un guard más confiable que un grep hecho a mano.** El barrido documentó que `awk` en su variante BSD/macOS no soporta `\b`, lo que habría dado falsos "OK" en un guard artesanal.
6. **Cadencia de release por bug, no acumulada, acelera la validación real.** Cada uno de los cinco fixes se liberó apenas se cerró (v0.14.0 → v0.14.4) porque cada release desbloqueaba el siguiente paso de la validación contra el consumidor: sin #299 el merge del batch seguía roto en repos squash-only; sin #302/#305 el gate abortaba por smoke tests ajenos al cambio real.
